# Mystery Case Script

Create evidence-led stories in which a concrete question, people and discoveries carry the episode. Adapted from the user's supplied Claude package with changes approved on 2026-09-08. Its worked examples and production tracker are reference material, not verified case evidence or the user's confirmed production history.

## Routing and authority

Read the project's AGENTS.md, README.md, registry.json and STORYTELLING.md when present. Session instructions override this skill. In this user's channel, prepare the full Vietnamese review script before English narration for US viewers; English follows user approval. Do not require a separate outline approval unless requested. The script request authorizes research, outlining and the Vietnamese draft together.

The channel covers documented real mysteries and criminal cases. Financial crime is an optional branch. Never force a false theory, a fixed number of clues, one reversal, a systemic failure or a fixed runtime onto a case. Resolution may be partial if the ending explains the evidential limits.

## Workflow

1. For selection, read [case-selection](references/case-selection.md). Use the project registry for duplicate control. User selection bypasses editorial scoring thresholds, not evidence verification.
2. Before prose, read [research-and-verification](references/research-and-verification.md); build a source inventory, timeline, claim ledger and gaps. Verify current developments that could change the ending.
3. Read [story-architecture](references/story-architecture.md) and [hook-library](references/hook-library.md). Outline what each person knew, what viewers know, how clues change meaning and what evidence causes each turn.
4. Read [voice-and-narration](references/voice-and-narration.md). Write the complete experience, not a synopsis. Mark claims in the working script; provide a clean reading copy separately.
5. Read [tts-formatting](references/tts-formatting.md) when preparing narration. Check fact accuracy, pacing, source attribution, current platform guidance and actual audio separately; do not claim audio verification without listening.

Use the project episode template if available, otherwise [case brief](assets/case-brief-template.md) and [script template](assets/script-template.md). Save only real artifacts. Mark review drafts awaiting_review, never scripted or published prematurely.

## Editorial invariants

- A wrong theory must be genuinely documented and attributed as a belief. Do not misstate facts or suppress known exculpatory evidence to implicate someone.
- Explain what an investigative step seeks before its result, then explain what the result does and does not establish.
- Give the solution room to connect earlier clues; avoid repeating the whole story after the reveal.
- Humanize victims through relevant, sourced life details. Do not invent dialogue, scene conditions, feelings or a minute-by-minute reconstruction.
- Use neutral, precise language and only necessary non-graphic detail. Word substitution alone does not ensure platform compliance or advertising eligibility.
- CTA defaults to one optional sentence after the ending. No sponsorship copied from references.
- No automatic sending, publication, payments, source contact or importing external case-status claims.
